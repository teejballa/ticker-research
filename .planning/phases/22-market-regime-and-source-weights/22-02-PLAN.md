Existing pattern (P27 backfill cron — checkpoint + auto-disable):
- ENV var `BACKFILL_*_DISABLED` short-circuits the handler with a 200 + summary.
- ENV var `BACKFILL_*_CHECKPOINT` stores the last-processed row id; resume from there on next invocation.
- Per-tick budget: process up to N rows, then return 200 with `next_checkpoint`. Vercel re-invokes on schedule.
- Cron schedule frequency MUST honor the <cron-jobs> skill: Pro plan = down to once per minute; Hobby = once per day.

```typescript
// File: src/app/api/cron/backfill-regime/route.ts
export async function POST(request: Request) {
  const authHeader = request.headers.get('authorization');
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return new Response('Unauthorized', { status: 401 });
  }

  if (isRegimeBackfillDisabled()) {
    return Response.json({ status: 'disabled', reason: 'auto-disabled after complete pass' });
  }

  // 1. Sweep SentimentSnapshot WHERE regime='ALL' ORDER BY scanned_at LIMIT N.
  // 2. For each row: classifyRegimeAt({ asOf: row.scanned_at }) → update.
  // 3. Sweep PerSourceIC WHERE regime='ALL' ORDER BY computed_at LIMIT N.
  // 4. For each row: classifyRegimeAt({ asOf: row.computed_at }) → update.
  // 5. If no rows remain → set BACKFILL_REGIME_DISABLED=true (write to env via Vercel API or .env.local for local).
  // 6. Return { processed_snapshots, processed_ic_rows, next_checkpoint }.
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Cron → `/api/cron/backfill-regime` | Authenticated via `Authorization: Bearer ${CRON_SECRET}` per `<cron-jobs>` skill. |
| Operator → manual cron POST | Same Bearer guard. Operator must store CRON_SECRET locally; no new attack surface. |
| Cron route → Neon | Existing Prisma singleton; only UPDATEs `SentimentSnapshot` + `PerSourceIC` rows by id (no DELETE, no schema change). |
| Cron route → yahoo-finance2 / Polygon | Existing wrappers with `withTelemetry`; circuit breaker from P30 applies. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02-01 | Spoofing | Unauthenticated invocation of `/api/cron/backfill-regime` | mitigate | Bearer `CRON_SECRET` guard (matches `/api/cron/relabel`). 401 on missing/wrong header. Unit test asserts this. |
| T-22-02-02 | Tampering | Backfill writes wrong regime for a row | mitigate | Pure functional classifier; `@knowable_at` audit; idempotent re-run resets via cleared `BACKFILL_REGIME_DISABLED`. |
