## What Was Built

### Task 1 — patternStatus 5-gate rewrite (`src/lib/learning.ts`)

The existing `patternStatus` function (ESS + drift checks only) was replaced with a strict 5-gate implementation per D-26. A cell achieves `ACTIVE` only when **all five** gates pass:

- **(a)** `effective_sample_size ≥ 30` — ESS gate (Phase 18 rule preserved)
- **(b)** `live_outcome_count ≥ 10` — live-only gate (Phase 27 D-10 rule preserved via `LIVE_OUTCOME_THRESHOLD`)
- **(c)** `(brier_null - brier_out) > BRIER_LIFT_THRESHOLD` — OOS Brier-lift gate; `BRIER_LIFT_THRESHOLD = 0.005` exported constant; strict `>` not `>=`
- **(d)** `by_fdr_q_value < 0.10` — Benjamini-Yekutieli FDR; `null` → fail (caller must supply after BY run)
- **(e)** `dsr > 0` — Deflated Sharpe Ratio; `null` → fail (T<30 or missing returns stream)

DEPRECATED rules (`brier_out > brier_null`, `|drift_z| > 2`) fire first and are fully preserved. Any single gate failure returns `EXPLORATORY`. New `EXPLORATORY-WATCH` status is returned only via the drift state machine in the cron (not directly from `patternStatus`).

New exports added:
- `BRIER_LIFT_THRESHOLD = 0.005`
- `LEARNING_EVENT_TYPES` const + `LearningEventType` type (adds `cell_promoted`, `cell_demoted`, `logistic_anneal`)
- `initLogisticStateForN(featureNames, n)` — wires `priorPrecisionForN(n)` (returns 8/4/1 for n<100/500/∞) into a fresh `LogisticState`

### Task 2 — Two-pass BY-FDR architecture in `/api/cron/learn` (`route.ts` + test)

The original `recomputeOneCell` (void, wrote status directly) was split into a two-pass architecture:

**PASS 1 — evaluate all cells:**
`evaluateOneCell(key)` returns `CellEvalResult | null`. Each call:
1. Runs all existing Phase 18/19/27 logic (decay, ESS, Brier OOS, drift) unchanged
2. Builds `cvObs: Observation[]` from weighted events
3. Runs `purgedKFold` (5 folds, 90-day purge + embargo) to compute fold-wise Brier lifts
4. Computes `bootstrapBCa` 95% CI on fold lifts; derives one-sided p-value
5. Computes `deflatedSharpeRatio` on `forward_return_sector_rel` stream
6. Counts `live_outcome_count` (events where `delta.source !== 'backfill'`)
7. Returns all computed values without calling `patternStatus` or writing to DB

**BY-FDR denominator:**
`benjaminiYekutieli(pValues, 0.10)` runs once over all collected p-values. The denominator correctly spans the full set of cells evaluated in this cron run (not per-cell), controlling for the ~156-cell dependence structure.

**PASS 2 — apply status and emit events:**
`applyPatternStatusAndEmitEvents(evals, fdrAdjustedP)`:
- Calls `patternStatus` with BY-FDR q-values now known
- Applies drift/watch state machine (D-09) and `enforceLiveOnlyGate` safety layer
- Writes `learnedPattern.update` with resolved status
- Emits existing `drift_alert`/`drift_clear` LearningEvents (preserved)
- Emits `cell_promoted` or `cell_demoted` LearningEvent when status changes, with full D-27 delta payload containing all 8 required keys: `cv_folds`, `brier_lift`, `brier_lift_ci_bca_95`, `q_value_by`, `dsr`, `n_trials_attempted`, `prev_status`, `new_status`

**Test suite (`learn-promotion-event.test.ts`):**
24 unit tests + 1 live-gate skipped across 6 groups:
1. `patternStatus 5-gate — promotion contract` (11 tests): ACTIVE when all pass; each gate individually failing → non-ACTIVE; DEPRECATED rules preserved
2. `benjaminiYekutieli — BY-FDR contract` (5 tests): reject/accept logic, edge cases, length preservation
3. `deflatedSharpeRatio — DSR contract` (3 tests): positive Sharpe → >0; T<30 → null; deflation with 156 trials
4. `bootstrapBCa — lift CI contract` (2 tests): CI contains true mean; low≤point≤high
5. `Full promotion scenario` (3 tests): p→BY→q→ACTIVE path; noise → no promotion; delta payload has all 8 required keys
6. `RUN_LIVE_INTEGRATION gate` (1 live skipped)

## IS-Paper Note

The rigorous 5-gate design intentionally produces a high bar. If no cell graduates to ACTIVE after a full soak (157 cells × 3 horizons = 471 regime slots), that is a valid IS-paper finding: "the engine observed no cell with simultaneous ESS≥30, live≥10, OOS Brier-lift>0.5%, BY-FDR q<10%, and DSR>0." This outcome confirms the engine is not producing spurious promotions and provides honest calibration for the paper's Section IV (results and limitations).
