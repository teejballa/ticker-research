## What Was Built

### Task 1 — `/api/cron/llm-ic/route.ts` + `vercel.json`

Daily cron at 09:30 UTC implementing CORE-ML-20 direct LLM evaluation:

- **Step A** (new predictions): for each Report in last 60d, extracts `analysis.assessment.buy_pct/sell_pct` to compute `s = (buy_pct - sell_pct) / 100` ∈ [-1,+1]; inserts `LLMEvaluation` rows for horizons [7, 14, 30] with idempotency guard (`findFirst` before `create`)
- **Step B** (resolution): for unresolved rows whose horizon has elapsed, joins `PriceOutcome` to get `forward_return_sector_rel` and `is_sigma_hit_k1`; computes `brier_buy_prob = (p_buy - hit)^2` where `p_buy = (s + 1) / 2`; writes `is_resolved=true`
- Returns `{ok, n_new_predictions, n_resolved, n_total_active}`
- `vercel.json`: `"30 9 * * *"` added after existing `"0 9 * * *"` baseline-eval

### Task 2 — `src/lib/engine-context.ts` additions

Three reader functions enforcing D-30 trust boundary (no dashboard component reads DB directly):

**`getLLMICRolling(windowDays=30)`** — Surface 2 headline:
- Reads resolved `LLMEvaluation` rows in last N days
- Headline IC: Spearman rank-correlation (informationCoefficient); BCa 95% CI (B=10,000)
- Sliding-window series: one IC + CI per calendar day (B=2,000 for performance)
- Verdict: `COLLECTING_DATA` (n<30), `EDGE_DETECTED` (CI.low>0), `NEGATIVE_EDGE` (CI.high<0), `INCONCLUSIVE` (CI spans 0)

**`getBaselineComparison(horizon)`** — Surface 1 source:
- Reads most recent `baseline_eval` LearningEvent delta for engine36/canonical7 metrics
- Computes LLM IC and Brier from LLMEvaluation rows at the requested horizon
- Returns 3 rows (brier/ic/log_loss) × 4 columns (llm/logistic24/logisticCanonical/null) with BCa CIs

**`getPerSignalIC()`** — Surface 4 source:
- Reads `LearnedPattern.rolling_ic_20d` grouped by signal_class
- BCa 95% CI per class; sorted by |IC| descending

### Task 3 — Components

**`RollingLLMICTile`** (server): 36px Inter Tight 600 tabular-nums headline IC; 4-state verdict badge (teal/rose/amber/neutral); BCa CI metadata (10px JetBrains Mono); inline SVG sparkline (600×180, CI band = indigo @ 10% opacity, zero reference dashed line, x-axis date labels); COLLECTING DATA skeleton with `animate-pulse`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Report model has no `assessment` or `confidence_pct` columns**
- **Found during:** Task 1 implementation
- **Issue:** The plan's action block referenced `report.assessment` and `report.confidence_pct` as direct Report model fields. The actual schema stores `confidence_level: String` (Low/Medium/High enum) and the structured assessment inside `analysis: Json` (the Gemini output Zod schema's `assessment.buy_pct/sell_pct/hold_pct`).
- **Fix:** `extractSignedScore()` reads `analysis.assessment.buy_pct` and `analysis.assessment.sell_pct` (authoritative source from the Zod schema); falls back to `confidence_level` + `market_sentiment` string direction for older records. `s = (buy_pct - sell_pct) / 100` is equivalent to the D-08 signed score.
- **Files modified:** `src/app/api/cron/llm-ic/route.ts`
- **Commit:** `692255d`

**2. [Rule 2 - Missing critical functionality] @@unique constraint deferred to use findFirst guard**
- **Found during:** Task 1 — plan action block mentioned adding `@@unique([report_id, horizon_days])` to the schema but also recommended the `findFirst` approach to avoid a migration.
- **Fix:** Used `findFirst` idempotency guard (check before create) instead of unique constraint. This avoids a migration Wave 5 doesn't own. The plan explicitly endorsed this as the preferred approach.
- **Files modified:** `src/app/api/cron/llm-ic/route.ts`
- **Commit:** `692255d`

**3. [Rule 2 - Missing implementation] Report model missing `created_at` — use `analyzed_at`**
- **Found during:** Task 1 — plan action block referenced `report.created_at` in the 60-day filter.
- **Fix:** Report schema has `analyzed_at: DateTime` (not `created_at`). Used `analyzed_at: { gte: since }` in the Prisma query.
- **Files modified:** `src/app/api/cron/llm-ic/route.ts`
- **Commit:** `692255d`

### Design Decisions

- **PerSignalICTable color coding**: Added teal/rose coloring when the IC's BCa CI fully excludes zero (positive → teal, negative → rose), matching the existing `PatternsTable` convention. The UI-SPEC was silent on this per-row coloring; this is additive.
- **BaselinesComparisonTable coloring direction**: LLM column always renders in ink (it's the reference). Comparator columns (Logistic-24 / Logistic-canonical) are colored relative to LLM — rose when the comparator beats LLM (LLM loses), teal when LLM beats the comparator. This is the IS-paper framing: "does LLM beat the baseline?"
