# Phase 21.1: Capacity to Detect Edge — Context

**Gathered:** 2026-06-02
**Status:** Ready for planning
**Driver:** Post-P27 diagnostic showed engine measures noise correctly but cannot detect edge — hit rates ~35–48% match random-walk null for the current 1% sector-relative threshold. No IC, no bootstrap CIs, no FDR gate, no LLM-direct evaluation, no logistic baseline. This phase ships the capacity to find edge if it exists.

<domain>
## Phase Boundary

Equip Cipher's learning engine and reporting layer with the rigor + capability to **detect edge if it exists**, with publication-grade evaluation. Combines newly-scoped measurement infrastructure with Phase 23's previously-planned lift-gated promotion (CORE-ML-15..19) into a single consolidated phase.

**In scope:**
- Information Coefficient (IC), Bootstrap CIs, BY-FDR, log-loss, Deflated Sharpe Ratio primitives
- Direct LLM evaluation against forward returns (IC + Brier on every report)
- Logistic baselines (Bayesian Laplace, both 24-feature and canonical small set)
- σ-aware hit threshold (k=1, 60d sector σ) becomes primary engine label
- Directional + 1%-flat labels retained as secondary diagnostics
- Z-score feature companions: ticker-rolling-60d AND cross-sectional (12 → 36 features)
- FDR-gated, DSR-screened ACTIVE promotion in `patternStatus()`; `LearningEvent` cell_promoted/demoted
- `knowable_at` as-of-time audit script; CI gate to block lookahead introductions
- Dashboard tiles: three-way LLM vs Logistic-24 vs Logistic-canonical vs Null Brier; rolling LLM IC with CI band; per-signal-class IC table

**Out of scope (deferred to P21.2 / P22 / later):**
- GBM / XGBoost baseline (P21.2)
- Cross-signal cells (insider × technical etc.) (P21.2 — GBM gets interactions for free)
- Embedding-rich logistic with full SourcePackage inputs (P21.2 — biggest single comparability gain)
- Event-conditional predictions (PEAD windows, post-13F windows) (P21.3)
- Full LLM backtest on historical SourcePackages — ~$600 in Gemini, 12k+ predictions for power (P21.4 — paper-grade evaluation)
- Conformal prediction intervals on returns (deferred per Phase 21 non-goal)
- Lo-Mamaysky-Wang conditional-distribution evaluation (deferred per Phase 21 non-goal)

**Phase 23 retired:** P21.1 absorbs CORE-ML-15..19 entirely. REQUIREMENTS.md must be updated to remap those requirements to Phase 21.1.

<decisions>
## Implementation Decisions

### Scope vs prior planning

- **D-01:** P21.1 absorbs **Phase 23 (Lift-gated cell promotion) entirely**. All of CORE-ML-15, CORE-ML-16, CORE-ML-17, CORE-ML-18, CORE-ML-19 ship in this phase. Phase 23 is retired. No progress lost — REQUIREMENTS.md will be remapped during planning.
- **D-02:** FDR test family = **Benjamini-Yekutieli (BY)**, not Benjamini-Hochberg (BH). BY is dependence-robust, which is correct for the 156-cell setup where cell hit-rates are not independent (shared market regime). Honors REQUIREMENTS.md CORE-ML-17 verbatim.
- **D-03:** **Deflated Sharpe Ratio** per Bailey & López de Prado computed on every cell that crosses the ACTIVE candidate threshold. Honors CORE-ML-18.
- **D-04:** `LearningEvent` rows of type `cell_promoted` / `cell_demoted` written with full evaluation context (CV folds, lift, q-value, DSR, n_trials_attempted). Honors CORE-ML-19.
- **D-05:** `n_trials_attempted` recorded per `learn` cron run as the FDR denominator. Honors CORE-ML-17.
- **D-06:** Out-of-sample evaluation uses the **existing `src/lib/cv.ts` Purged K-Fold + Embargo** implementation. Honors CORE-ML-16. No new CV framework.
- **D-07:** Brier-lift threshold for ACTIVE candidacy = **Claude's Discretion**. Researcher picks data-driven value via sensitivity sweep on the backfill corpus. Document chosen value + sensitivity table in `HYPERPARAMETERS.md`.

### LLM direct evaluation

- **D-08:** LLM scored against forward sector-relative returns via **both IC and Brier**:
  - **IC:** Spearman rank-correlation between LLM's confidence-weighted directional score `s ∈ [-1, +1]` (where `Buy = +confidence`, `Hold = 0`, `Sell = -confidence`) and forward `sector_relative_pct` at each horizon. Standard quant convention.
  - **Brier:** On LLM's Buy-probability vs the binary "did it beat sector by ≥1σ" (the new primary label, D-13).
- **D-09:** Score **every prediction**, no confidence filter. Hold calls with 50% confidence count. Maximizes sample size and tests whether LLM "no-edge" calls actually have no forward edge (self-calibration test).
- **D-10:** Rolling 30-day LLM IC tile on `/insights` with **BCa bootstrap 95% CI band** (10k resamples). The headline IS-paper figure.

### Logistic baseline (head-to-head against LLM)

- **D-11:** Ship **two logistic baselines side-by-side**:
  - **24-feature post-z-score** (the engine's full feature space) — strongest "LLM beats numeric features" claim
  - **Canonical small set** (5–7 features: RSI, MACD, sentiment%, insider net flow, institutional net flow, put/call ratio, sector return) — strongest "LLM beats lit-cited features" claim
- **D-12:** Both logistics use **Bayesian logistic with Laplace approximation** — extends the existing `predictLogistic` / online update in `src/lib/learning.ts`. Same evaluation pipeline as the engine; no new framework.
- **D-13:** Ridge sweep on `PRIOR_PRECISION` (e.g., {1, 2, 4, 8, 16}) per logistic; pick the value minimizing OOS Brier on Purged K-Fold. Document chosen precision per baseline in `HYPERPARAMETERS.md`.

### Target labels + threshold

- **D-14:** **σ-aware hit threshold becomes primary engine label.** Parameters: `k = 1`, 60-day rolling sector ETF σ. `classifyHit` already supports this signature — wire `sector_sigma` into the call site in `/api/cron/relabel` and `/api/cron/price-followup` via a new 60-day rolling-σ helper in `src/lib/data/sector-mapping.ts`.
- **D-15:** **Directional label** (`is_directional_hit`: beat sector by >0%) written as secondary diagnostic — used for the higher-SNR comparison in the dashboard and the IS paper, NOT the engine's primary gate.
- **D-16:** **1% flat label** (current `is_hit`) retained as a tertiary diagnostic for back-compat with existing dashboards and the relearn baseline. All three labels written on every new `PriceOutcome`.
- **D-17:** All three labels are written by **one shared compute path** in `relabel` / `price-followup` (single source of truth, train/serve skew defense per CLAUDE.md rule #6).

### Feature engineering

- **D-18:** Z-score feature companions: **both ticker-relative rolling AND cross-sectional**.
  - **Ticker-relative:** 60-day rolling z-score of each base feature vs the same ticker's own 60d history (12 new features)
  - **Cross-sectional:** z-score of each base feature within today's `BACKFILL_UNIVERSE` (12 new features)
  - Total feature dimension: 12 base + 12 ticker-rolling + 12 cross-sectional = **36 features** for the engine's 12-d logistic (now 36-d).
- **D-19:** `PRIOR_PRECISION` annealing schedule for the engine's 36-feature logistic: **8 when n<100, 4 when 100≤n<500, 1 when n≥500**. Document in `HYPERPARAMETERS.md`. Honors ISL Ch. 6 ridge/lasso shrinkage when sparse.
- **D-20:** Every feature gets a `knowable_at` as-of-time annotation. New CI script `scripts/check-feature-asof.ts` blocks merges that introduce features without it. Honors CLAUDE.md rule #6 (feature-leakage audit at every data-source addition).

### Measurement primitives

- **D-21:** `src/lib/evaluation/ic.ts` — `informationCoefficient(predictions, returns, method='spearman')`. Per signal class, per horizon, with rolling-window variant.
- **D-22:** `src/lib/evaluation/bootstrap.ts` — `bootstrapCI(samples, statistic, n=10000, method='bca')`. BCa (bias-corrected accelerated) per ISL Ch. 5. Used on every reported number.
- **D-23:** `src/lib/evaluation/fdr.ts` — `benjaminiYekutieli(pValues, q=0.10)`. Returns adjusted p-values and ACCEPT/REJECT decisions. Used in `patternStatus` and in any cross-cell claim in the dashboard.
- **D-24:** `src/lib/evaluation/dsr.ts` — `deflatedSharpeRatio` per Bailey & López de Prado. Computed on each ACTIVE-candidate cell using `n_trials_attempted` from the parent `learn` run.
- **D-25:** `src/lib/evaluation/log-loss.ts` — Categorical log loss for the 3-way Buy/Hold/Sell distribution. Computed alongside Brier per CLAUDE.md rule #7 (proper scoring rules).

### Promotion gate

- **D-26:** `patternStatus()` rewritten — a cell graduates to ACTIVE only when ALL of: (a) ESS ≥ 30 per existing rule, (b) ≥10 live (non-backfill) outcomes per Phase 27 D-10, (c) OOS Brier-lift > threshold (D-07) on Purged K-Fold, (d) BY-FDR q-value < 0.10 across the `learn` run's `n_trials_attempted`, (e) DSR > 0. Any failing gate → EXPLORATORY (or DEPRECATED if `brier_out > brier_null` per existing logic).
- **D-27:** Cell-status flips emit `LearningEvent` of type `cell_promoted` / `cell_demoted` with the full evaluation context (CV folds, lift, q-value, DSR, n_trials_attempted) per CORE-ML-19.

### Dashboard

- **D-28:** New page `/insights/baselines` — three-column table (LLM / Logistic-24 / Logistic-canonical / Null) showing IC + Brier + log-loss with bootstrap CIs, per horizon, FDR-corrected.
- **D-29:** Existing `/insights` extended with: (a) rolling 30-day LLM IC tile with CI band (D-10 headline); (b) per-signal-class IC table; (c) ACTIVE-cell DSR column on existing PatternsTable.
- **D-30:** All numeric flowing into the dashboard sourced from `engine-context.ts` per the existing trust-boundary non-negotiable. No new LLM-produced numerics.

### Claude's Discretion

- BCa bootstrap implementation details (acceleration computation, edge cases at n<50).
- Exact Brier-lift threshold value for ACTIVE candidacy (D-07) — researcher picks via sensitivity sweep on backfill.
- Ridge precision values to sweep (D-13) — researcher picks set.
- Internal organization of the `evaluation/` namespace (D-21..25) — planner decides.
- Cron schedule for the new logistic-baseline cron (`/api/cron/baseline-eval`) — planner picks a window that doesn't conflict with existing crons.
- Whether to add a tree-based feature-importance report on the 36-feature space (deferred to P21.2 if dimensionality becomes a problem).
- UI styling for the three-way comparison table — follow existing Insights layout patterns.

</decisions>

## Deferred Ideas

### Pulled into P21.2
- **GBM / XGBoost baseline** on the same 36-feature space + canonical small set. CLAUDE.md rule #8 mentions tree-based; ISL Ch. 8 ("Tree-Based Methods"). Gets cross-feature interactions for free. Plan for P21.2.
- **Cross-signal cells** (e.g., `insider+technical/large_cap/7d`) materialized when both signals fire on the same snapshot. Document empirical lit (Cohen-Malloy-Pomorski + technical) supporting interaction effects. Plan for P21.2 alongside GBM.

### Pulled into P21.3
- **Event-conditional predictions**: PEAD windows (post-earnings drift, Bernard & Thomas 1989), post-13F windows (Wermers 1999), post-insider-cluster windows (Jeng/Metrick/Zeckhauser 2003). Highest-edge per the lit. Requires earnings-calendar infra.

### Pulled into P21.4 (paper-grade)
- **Full LLM backtest on historical SourcePackages** — Replay Gemini against ~12,584 PIT SourcePackages (121 tickers × 52 weeks × 2 years). Cost ≈ $630. Produces the publication-grade dataset for the IS paper's headline claim. Defer until P21.1 + P21.2 + P21.3 capability is in place.

### Possibly absorbed into later phases or kept deferred
- **Embedding-rich logistic with full SourcePackage inputs** (the third logistic baseline option from gray-area #3). Requires embedding choice as its own gray area. Plan for P21.2 alongside GBM if engineering surface allows.
- **Triple-barrier labels** (López de Prado 2018) with volatility-scaled barriers at short horizons. Deferred in Phase 21 — keep deferred unless P21.1 results suggest fixed-threshold labels are still too noisy.
- **Hierarchical Bayesian sector pooling** — Phase 21 deferral preserved. Sector pooling is orthogonal to P21.1's measurement upgrade.
- **Conformal prediction intervals on returns** — Phase 21 deferral preserved.
- **Lo-Mamaysky-Wang conditional-distribution evaluation for chart patterns** — Phase 21 deferral preserved.
- **Causal-inference layer for signal attribution** — REQUIREMENTS.md v2.1+ deferral preserved.

### Phase 22 implications
- **Phase 22 (Market-Regime + Learned Sentiment-Source Weights)** was gated on a 1–2 week relearn soak after P21. With P21.1 in front of it (and absorbing Phase 23), the soak window slides. Recommendation: P22 discuss-phase eligible **after P21.1 ships** and the relearn produces post-FDR ACTIVE cells (or confirms none exist). If P21.1 yields no ACTIVE cells, P22's premise (tune sentiment-source weights based on what we learned) may need re-scoping or deferral.
