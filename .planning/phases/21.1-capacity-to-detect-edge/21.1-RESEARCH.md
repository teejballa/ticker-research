## 2. Primitives — formula + integration point

### 2.1 BCa Bootstrap (D-22)

**Formula** (Efron 1987 JASA — already cited in CLAUDE.md canonical_refs):
- Draw B resamples (B=10000) of the statistic θ̂*.
- Bias-correction `z₀ = Φ⁻¹(P(θ̂* < θ̂))`.
- Acceleration `a = Σ(θ̄ - θ̂₍ᵢ₎)³ / [6 · (Σ(θ̄ - θ̂₍ᵢ₎)²)^(3/2)]` from jackknife.
- Adjusted percentiles `α₁ = Φ(z₀ + (z₀ + z_{α/2}) / (1 - a·(z₀ + z_{α/2})))`, similarly α₂.

**Integration:** new module `src/lib/evaluation/bootstrap.ts` that supersedes the simple-percentile `bootstrap` function at `learning.ts:284` (`adversarialNullBrier` uses a related shuffle pattern — leave it alone; it answers a different question).

**Dependencies:** none — hand-roll. Need a Φ⁻¹ (inverse normal CDF) helper; rational-approximation per Beasley-Springer-Moro is ~30 LOC.

**Edge cases:**
- `n < 50`: acceleration estimate is unstable; fall back to plain percentile method with a logged warning. Document threshold in HYPERPARAMETERS.md.
- All resamples identical: emit CI = [θ̂, θ̂] and a `degenerate=true` flag.
- Statistic NaN on any resample: skip that resample, continue (do not zero-fill).

**Sources:** `[CITED: Efron 1987 JASA "Better Bootstrap Confidence Intervals"]`, `[CITED: ISL 2nd ed. Ch. 5]`.

### 2.2 Benjamini-Yekutieli FDR (D-23)

**Formula** (Benjamini & Yekutieli 2001 — dependence-robust):
Given p-values `p₁ ≤ p₂ ≤ … ≤ p_m` and target FDR `q`:
- `c(m) = Σᵢ₌₁^m 1/i` (harmonic number — the dependence correction)
- Reject `H₍ᵢ₎` if `pᵢ ≤ (i · q) / (m · c(m))`
- Adjusted p-value: `p_adj(i) = min(1, p(i) · m · c(m) / i)` then monotone-enforced from largest rank down.

**Integration:** new `src/lib/evaluation/fdr.ts`. Called from `patternStatus()` in `learning.ts` (D-26 gate (d)) and from the dashboard's 3-way comparison page (D-28) before any cross-cell claim.

**Why BY not BH** (per D-02): the 156 cells (4 signal classes × ~6 patterns × ~7 cap_classes × 6 horizons trimmed) are NOT independent — they share market regime, sector exposure, common tickers. BH assumes independence or positive regression dependence; BY assumes nothing.

**Edge cases:**
- `m = 0`: return empty, no exception.
- All `p = 0`: all reject.
- Single p-value (`m = 1`): BY collapses to identity, return as-is.

**Sources:** `[CITED: Benjamini & Yekutieli 2001, Annals of Statistics 29(4):1165-1188]`, `[CITED: ISL 2nd ed. Ch. 13]`.

### 2.3 Deflated Sharpe Ratio (D-24)

**Formula** (Bailey & López de Prado 2014):
```
SR̂ = mean(strategy_return) / std(strategy_return)        (sample Sharpe, here for the cell's hit-rate stream)
SR₀ = E[max of N trials Sharpe under null]                 (multiple-testing penalty)
    ≈ √(2·ln(N)) · σ_SR̂ − 0.5772·σ_SR̂/√(2·ln(N))         (Gumbel max approximation)
DSR = Φ((SR̂ − SR₀) · √(T−1) / √(1 − γ₃·SR̂ + (γ₄−1)/4·SR̂²))
```
where `N` = number of trials attempted (= `n_trials_attempted` per D-05), `T` = sample length, `γ₃, γ₄` = skewness and kurtosis of the strategy returns, `Φ` = standard normal CDF.

**Integration:** new `src/lib/evaluation/dsr.ts`. Computed inside `learn` cron for each ACTIVE-candidate cell. **The `LearnedPattern.dsr` column already exists** (added in Phase 19-Z-02 — see `schema.prisma:135`). Wire-up only.

**Key inputs from learn-cron context:**
- `n_trials_attempted` already populated by `learn` cron and stored on `LearnedPattern.n_trials_attempted` (schema.prisma:122). Use this as N.
- `T` = `effective_sample_size` (already on `LearnedPattern.effective_sample_size`).
- For γ₃, γ₄ compute from the cell's hit-stream sequence (0/1 with Brier-residuals as returns? or raw `sector_relative_pct` for the cell's outcomes? — **planner gray area**: recommend raw forward returns of the cell's outcome rows; document choice in HYPERPARAMETERS.md).

**Edge cases:**
- `N = 1`: SR₀ = 0, DSR collapses to SR-significance test.
- `T < 30`: skip DSR, write `null`, document "insufficient sample" in eval context.

**Sources:** `[CITED: Bailey & López de Prado 2014, J. Portfolio Management]`.

---

### 2.4 Spearman IC (D-21)

**Formula:** Rank-correlation between predictions `s ∈ [-1, +1]` (D-08) and forward returns. With ties:
```
ρ_s = 1 − (6 · Σ(d_i²) / (n·(n²−1)))     (no ties)
ρ_s = (Σ(R_x·R_y) − n·R̄_x·R̄_y) / (n · σ_{R_x} · σ_{R_y})  (with ties — use Pearson on ranks)
```
Use the with-ties form unconditionally — Hold = 0 generates ties.

**Integration:** new `src/lib/evaluation/ic.ts`. Three public functions:
- `informationCoefficient(predictions: number[], returns: number[], method='spearman'): number`
- `rollingIC(predictions: TimeStamped<number>[], returns: TimeStamped<number>[], windowDays: number): { t, ic }[]` — for D-10 headline tile.
- `perSignalClassIC(rows, groupBy): { class, ic, n }[]` — for D-29 per-signal-class table.

**Edge cases:**
- All predictions identical (all Holds): `σ_{R_x} = 0` → return `NaN` with a logged warning, dashboard renders "—" not "0".
- `n < 10`: return `NaN`, log "insufficient sample".

**Sources:** `[CITED: Standard quant convention — see Grinold & Kahn "Active Portfolio Management" §3]`, `[ASSUMED: tie-handling formula matches scipy.stats.spearmanr default]` — validate against scipy in unit test.

### 2.5 Log-loss (D-25)

**Formula** (CS229 "Information Theory"):
```
LL = − (1/n) · Σᵢ Σ_k 𝟙[yᵢ=k] · log(p_ik)
```
Three-way Buy/Hold/Sell. Clip `p ∈ [ε, 1−ε]` with `ε = 1e-15` to avoid `log(0)`.

**Integration:** new `src/lib/evaluation/log-loss.ts`. Called alongside Brier per CLAUDE.md rule #7.

**Edge cases:**
- Class missing from predictions but present in y: that row contributes `−log(ε)` ≈ 34.5 — exactly the punishment we want for overconfident wrong calls.
- Probabilities don't sum to 1: re-normalize with a warning.

**Sources:** `[CITED: CS229 main notes, "Information Theory" section]`.

**Note on `is_hit`:** the existing 1%-flat label per D-16 is currently NOT a column — it's computed at read-time via `classifyHit`. Two options:

- **Option A (recommended):** add `is_hit_flat1` BOOLEAN column too, populated by the same shared compute path per D-17. Three columns total. Persisting closes the loophole.
- **Option B:** leave `is_hit` as a read-time function, persist only the two new labels. Cheaper schema-wise but violates D-17's "single source of truth" spirit. **Do not pick this.**

→ **Recommendation: 3 BOOLEAN columns + 1 FLOAT (snapshotted σ).** Total: 4 additive nullable columns.

**`sector_sigma_60d` rationale:** the σ used at relabel time is needed at re-evaluation time for hindsight checks (e.g., "did we use the right σ?"). Phase 21 already established the precedent of snapshotting benchmark artifacts (`sector_etf` is snapshotted at prediction time, not re-resolved — see `schema.prisma:77` comment). 2. **DSR returns input choice.** DSR formula needs a return stream. For each cell, do we use (a) the binary hit-stream {0,1}, or (b) raw `forward_return_sector_rel` of the cell's outcomes? Bailey & López de Prado work with raw P&L returns. Recommend (b) — raw sector-relative returns. Plan documents in HYPERPARAMETERS.md.

Recommend: start with `0.005` (i.e., 0.5 percentage points of Brier-lift over null) as a conservative default; sensitivity sweep can tighten or loosen. Planner picks; document in HYPERPARAMETERS.md.

Or trim to a clean 5? Recommend keep all 7 (the lit-cited classics — Lo & Hasanhodzic 2010 on technicals, Cohen-Malloy-Pomorski on insider, Wermers on institutional, Bondt-Thaler on sentiment). Planner confirms or trims with rationale.

5. **Ridge precision sweep grid for canonical-7.** D-13 says `{1, 2, 4, 8, 16}` for the engine's 36-d logistic — same grid for the 7-d logistic? Smaller feature space → less need for aggressive shrinkage; recommend `{0.5, 1, 2, 4}`. Planner picks.
