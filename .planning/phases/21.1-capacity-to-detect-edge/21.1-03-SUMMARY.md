## Implementation Details

### Task 1: canonical-features.ts

`CANONICAL_FEATURE_NAMES` locked to 7 strings in D-11 order (rsi_14, macd_hist, sentiment_pct, insider_net_flow, institutional_net_flow, put_call_ratio, sector_return). `CanonicalSnapshot` interface carries one `@knowable_at snapshot.scanned_at` annotation per field plus individual field-level comments citing the source paper:

- RSI-14: Lo & Hasanhodzic 2010, "The Evolution of Technical Analysis"
- MACD histogram: Brock-Lakonishok-LeBaron 1992
- sentiment%: De Bondt & Thaler 1985
- insider net flow: Cohen-Malloy-Pomorski 2012
- institutional net flow: Wermers 1999
- put/call ratio: Pan & Poteshman 2006
- sector return: Lakonishok-Shleifer-Vishny 1994 / DGTW 1997

`buildCanonicalFeatures(snapshot)` iterates the locked names, substitutes 0 + console.warn for any null/non-finite value (cold-start safety). Pure function, no IO.

### Task 2: logistic.ts

Three exported functions, all pure:

- `trainBaseline(name, rows, opts)`: initialises `LogisticState` with `intercept_var = 1/priorPrecision` and `weight_vars = 1/priorPrecision` (bypasses the module-level `PRIOR_PRECISION=1` in learning.ts so the ridge sweep can vary freely), then iterates `updateLogistic` over rows in order.
- `scoreBaseline(state, rows, name)`: computes Brier (MSE on binary hit), binary cross-entropy log-loss, and Spearman IC vs forward_return. Returns null Brier/log-loss on empty input (not NaN/exception).
- `sweepPriorPrecision(name, rows, grid, cvFolds)`: iterates over the precision grid × cv.ts `Fold[]`, trains/evals per fold, records mean±std OOS Brier, returns the precision minimising mean OOS Brier.

`TrainingRow.features36` carries the pre-built 36-element vector (caller's responsibility). When absent, falls back to a zero vector with console.warn — acceptable during cold-start while Wave 4 wires real DiffusionTrace joins.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] cv.ts purgedKFold takes Observation[] not generic TrainingRow[]**
- **Found during:** Task 3 implementation
- **Issue:** The plan's interface description (`CVSplit { train: number[]; test: number[] }`) described a hypothetical interface. The actual `cv.ts` `purgedKFold` signature takes `Observation[]` (with `recorded_at`, `horizon_days`, `hit`, `cell_key`) and returns `Fold[]` (with `trainIdx`/`testIdx`). These types are not interchangeable.
- **Fix:** Built a parallel `Observation[]` from `rowDates[]` (same indices as `trainingRows[]`) for `purgedKFold`, then used `fold.trainIdx`/`fold.testIdx` to index into `trainingRows[]`. `sweepPriorPrecision` accepts `Fold[]` directly (the real type).
- **Files modified:** `src/lib/baselines/logistic.ts` (uses `Fold[]`), `src/app/api/cron/baseline-eval/route.ts` (builds Observation[])
- **Commits:** 96e66af, aa02ca0

**2. [Rule 1 - Bug] Prisma InputJsonValue type rejected 'as unknown as Record<string,unknown>' cast**
- **Found during:** Task 3 TypeScript check
- **Issue:** `prisma.learningEvent.create({ data: { delta: payload as unknown as Record<string,unknown> } })` produced `TS2322: Type 'Record<string, unknown>' is not assignable to type 'JsonNull | InputJsonValue'` because Prisma's `InputJsonValue` union includes array/primitive branches that `Record<>` doesn't satisfy.
- **Fix:** Used `Parameters<typeof prisma.learningEvent.create>[0]['data']['delta']` to extract the exact Prisma type for the cast.
- **Files modified:** `src/app/api/cron/baseline-eval/route.ts`
- **Commit:** aa02ca0 (fixed before commit)

**3. [Rule 2 - Missing] Pre-built features36 on TrainingRow (architectural clarity)**
- **Found during:** Task 2 design
- **Issue:** Plan pseudocode called `buildFeatureVector36(row.snapshot, row.history60d ?? {}, row.universe ?? {})` with 3 args, but the actual function signature is `buildFeatureVector36(trace, techSnap, techPattern, history60d, universe)` — 5 args, and `trace` is a `DiffusionTraceResult` that cannot be derived from a raw DB snapshot without a separate query chain.
- **Fix:** `TrainingRow.features36` carries a pre-built 36-element vector (cron/caller's responsibility). Cold-start zero fallback documented. Wave 4 will wire real DiffusionTrace joins. This is cleaner than re-deriving `DiffusionTraceResult` inside a pure scoring function.
- **Files modified:** `src/lib/baselines/logistic.ts`, `src/app/api/cron/baseline-eval/route.ts`
- **Commits:** 96e66af, aa02ca0
