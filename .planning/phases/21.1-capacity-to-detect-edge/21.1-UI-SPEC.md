Accent (indigo) reserved for — explicit list, no exceptions:
1. The rolling-IC sparkline stroke (D-10).
2. The "currently active" filter chip on the baselines page (e.g. the selected horizon tab: 3d / 7d / 14d / 30d).
3. The DSR column header on `PatternsTable` (subtle visual marker that this is a Phase-21.1 addition; ties to existing pattern of using indigo for "newly graduated" cells).
4. Footnote citation superscripts (e.g. the `[1]` linking to Bailey & López de Prado 2014 in the DSR tooltip).
5. The link to `/insights/baselines` from the `/insights` landing page.

Accent NOT used for:
- Regular text body, table values, or column headers (those use ink/on-surface tokens).
- Pure decoration. Every indigo pixel must be doing semantic work.

Semantic color usage in the 3-way comparison table (D-28):
- Cells where the LLM beats the corresponding logistic baseline on a metric with FDR-corrected p < 0.10 → `text-secondary` (teal) and a small `↑` glyph. The cell text remains JetBrains Mono.
- Cells where the LLM loses to a logistic with FDR-corrected p < 0.10 → `text-error` (rose) and `↓`.
- Cells whose CI overlaps the comparator's CI → `text-on-surface` (default ink) and no glyph. Most cells, statistically, will fall here. This is OK and is the IS-paper's honest baseline-pessimist defense.

Color contrast — all text/background pairs on Cipher Light meet WCAG AA at minimum:
- `text-on-surface` (`#1B1A17`) on `bg-surface` (`#FFFFFF`) → 16.0:1 (AAA)
- `text-on-surface-variant` (`#4A4640`) on `bg-surface` (`#FFFFFF`) → 9.3:1 (AAA)
- `text-outline` (`#7C766B`) on `bg-surface` (`#FFFFFF`) → 4.5:1 (AA — used for metadata only)
- `text-secondary` (`#0F8A5B`, teal) on `bg-surface` → 4.7:1 (AA)
- `text-error` (`#C84A4A`, rose) on `bg-surface` → 4.5:1 (AA)
- `text-primary` (`#2F44D6`, indigo) on `bg-surface` → 6.5:1 (AAA)

Label set: `3d` / `7d` / `14d` / `30d`. The default-selected tab is `7d` (matches existing engine convention).

| State | Badge copy | Badge color | Trigger |

### Empty / no-data states

| Surface | Heading | Body |
|---------|---------|------|
| Rolling-IC tile, n<30 | `Collecting data` | `The rolling 30-day window has n = {N} predictions. The tile activates once n ≥ 30. Cipher's daily LLM-IC cron writes one row per report.` |
| Per-signal-class IC table, no ACTIVE signal classes | `No signal class has enough data yet` | `Each signal class needs n ≥ 10 graded predictions in the last 30 days before its IC is reported. The table populates as the engine accumulates outcomes.` |
| `/insights/baselines`, both logistics insufficient | `Baselines training` | `Both logistic baselines need n ≥ 100 graded predictions before their out-of-sample Brier and IC are reported. Current: Logistic-24 has n = {N1}; Logistic-canonical has n = {N2}. Estimated to populate around {DATE}.` |
| PatternsTable DSR column, cell not ACTIVE-candidate | (cell renders) `—` | (tooltip on hover) `Deflated Sharpe Ratio is computed only on cells that cross the ACTIVE-candidate threshold (ESS ≥ 30, ≥ 10 live outcomes, OOS Brier-lift > θ). This cell hasn't crossed yet.` |

### Error states

The three surfaces are server-rendered with `engine-context.ts` reader functions (D-30). Errors are limited to:

| Error | UI copy |
|-------|---------|
| `engine-context` reader throws (DB down, query timeout) | `Could not load metrics. The dashboard reads through engine-context.ts; check the most recent /api/cron/learn run on the deployment.` rendered inside the affected tile/table with a `border-error` rose border. Page still renders other tiles. |
| Baselines comparison data has stale `last_updated` > 36h | Small amber pill above the table: `Last refreshed {N}h ago — baseline-eval cron has not run since {timestamp}.` Page still shows the (stale) data. |
| Specific cell's BCa bootstrap returned `degenerate=true` flag | Cell renders `—` with tooltip `Bootstrap returned degenerate samples (all identical). Reported as no-CI.` Same `degenerate` flag handling as Wave 1 BCa spec, §2.1 edge cases. |

### Destructive actions

None in this phase. All three surfaces are read-only. No "Reset baseline", no "Force re-eval", no "Delete cell". The `/api/cron/baseline-eval` and `/api/cron/llm-ic` crons run on schedule and the UI reflects whatever `engine-context.ts` returns.

### Methodology micro-copy (for tooltips and inline footnotes)

Every statistical primitive used on-screen MUST have a tooltip/popover that names the primary source. This is the IS-paper rigor signal — every reported number is auditable.

| Symbol / metric | Tooltip body |
|---|---|
| `IC` | `Information Coefficient — Spearman rank correlation between predictions and forward sector-relative returns. Convention: Grinold & Kahn, Active Portfolio Management, §3.` |
| `Brier` | `Brier score — mean squared error of probabilistic forecasts vs binary outcome. Lower is better. Reference: Brier 1950, Monthly Weather Review.` |
| `Log-loss` | `Categorical log-loss across Buy / Hold / Sell outcomes. Lower is better; clips probabilities to [1e-15, 1-1e-15]. Reference: CS229 main notes, "Information Theory".` |
| `DSR` | `Deflated Sharpe Ratio — penalizes Sharpe for the number of trials attempted (n_trials_attempted). DSR > 0.95 ≈ statistically significant after multiple-testing correction. Reference: Bailey & López de Prado 2014, J. Portfolio Management.` |
| `q-value` (the BY-FDR column) | `Benjamini–Yekutieli adjusted p-value, dependence-robust. ACTIVE promotion requires q < 0.10 across the n_trials_attempted denominator. Reference: Benjamini & Yekutieli 2001, Annals of Statistics.` |
| `95% CI` | `BCa (bias-corrected, accelerated) bootstrap confidence interval, 10,000 resamples. Falls back to percentile method when n < 50. Reference: Efron 1987, JASA "Better Bootstrap Confidence Intervals".` |

Use `<abbr title="…">` for screen-reader access at minimum; preferred: a small `[?]` indigo superscript that toggles a popover.

- Every numeric cell renders `tabular-nums` so values align vertically — critical for visual scanning per the IS-paper symposium use case.

### Component spec

- **Status badge:** `<span className="inline-flex items-center gap-1.5 rounded-full bg-secondary-fixed px-2.5 py-1 text-[10px] font-mono font-semibold uppercase tracking-[0.2em] text-on-secondary-fixed">EDGE DETECTED</span>` for positive edge.   - **CI band:** `<path d="…" fill="var(--indigo)" fillOpacity="0.10" />` — the area between upper and lower 95% bounds. This is the headline visual; the band MUST be visually prominent so the reader instantly sees uncertainty.
  - **Center line:** `<polyline points="…" stroke="var(--indigo)" strokeWidth="2" fill="none" strokeLinecap="round" strokeLinejoin="round" />`.
  - **Zero reference line:** `<line x1=0 x2=600 y1=… y2=… stroke="var(--outline-variant)" strokeDasharray="4 4" />`.

### Accessibility

- The status badge is a visual signal. Add `aria-label` describing the verdict in plain English: `aria-label="Edge detected — 95% confidence interval excludes zero on the positive side"`.
- The SVG sparkline has `role="img"` and `aria-label="Rolling 30-day Information Coefficient: {N} measurements between {start} and {end}, currently at {value} with 95% confidence interval from {low} to {high}"`.

## Why these choices — IS-paper symposium framing

This contract makes one deliberate aesthetic choice: it favors **editorial / academic-paper density** over dashboard-app polish. Specifically:

- All numerics in monospace (JetBrains Mono) — matches how the IS paper itself will set tables.
- 10px UPPERCASE `tracking-[0.3em]` column heads — matches a printed-paper column-rule aesthetic, and matches what `PatternsTable.tsx` already established (committed 2026-05-16).
- Every primitive (IC / Brier / DSR / q-value / 95% CI / BCa) is linked to its primary source in a tooltip. The dashboard is therefore self-documenting; a symposium reviewer who screenshots `/insights/baselines` sees citation provenance baked into the visual.
- The single bold accent (indigo) is reserved for exactly five semantic uses. Not for "all interactive elements" — that would dilute the signal. The reader's eye is trained: indigo = Phase 21.1 contribution.
- Status badges are colored but always accompanied by a text label (`EDGE DETECTED`) and an `aria-label` describing the verdict in English. The IS-paper screenshot will be intelligible to a reader who's color-blind.

Per CONTEXT.md `<specifics>`: the user picked "the most ambitious technically-defensible option at every gray area." This contract translates that ambition into UI: a publication-grade dashboard, not a generic insights view.
